# 双11专鉴活动新增功能埋点方案

本方案用于开发接入、测试验收和活动复盘，覆盖活动入口、专鉴提交、累计发券、每日赠券、扭蛋抽奖、抽后引导、我的抽奖券、我的奖品、王者榜及防刷规则。核心链路是“看到活动 → 提交专鉴 → 获得抽奖券 → 抽奖 → 再次专鉴”，每一步分别记录用户行为和实际业务结果。

本次交付为埋点设计，尚未接入生产 SDK 或数据平台。表内英文事件名是统一命名建议；已有等价事件优先复用并补齐属性，不能再发一套重复事件。

## 最新业务口径

| 项目 | 统计采用的规则 |
|---|---|
| 活动时间 | 暂定北京时间 2026-10-27 00:00:00（含）至 2026-11-11 00:00:00（不含）；以实际上线配置为准 |
| 限免范围 | 全部用户、全部专家鉴定品类免费；免费资格与参与抽奖活动资格分别记录 |
| 活动品类 | 预留美妆、美妆无损、包袋、鞋靴、服饰、手表、3C数码、3C无损 8 类；按提交时生效配置判定 |
| AI 转专鉴 | 美妆无损不展示 AI 结果后的专鉴卡片；其余按该入口生效配置判断是否应展示 |
| 计次时点 | 活动品类订单提交成功即累计；同一订单仅计一次，不等待最终鉴定结果 |
| 里程碑 | 每 2 单普通券 1 张；第 10、20、30……单高级券 1 张，替代该节点普通券；跨天累计、无上限 |
| 每日券 | 每个符合条件用户每日自动到账 1 张普通券，当天有效；首次介绍绑定首赠券，次日不重复介绍或提醒 |
| 首次引导 | 固定未中奖绑定首次免费引导赠券本身；五连含该券时只影响那一次抽取；过期不转移到其他券 |
| 普通奖池 | 小样实物合计 5%，专家线上鉴别券 75%，再接再厉 20% |
| 高级奖池 | YSL 气垫、COACH 腰带、雷蛇耳机、COACH 钱包实物合计 8%，专家线上鉴别券 72%，再接再厉 20% |
| 实物限制 | 双11两池合计每人最多中 1 次实物，与卡牌活动独立；实物不可中或该池全部售罄时，其概率全部转给鉴别券，成为 80% / 20% |
| 两种券 | 抽奖券用于抽奖；中奖所得“专家线上鉴别券”用于免费专鉴，二者的发放、使用和过期分别统计 |
| 鉴别券有效期 | 双11奖品券有效至 2026-12-12 23:59:59，北京时间；卡牌存量券保留原记录有效期 |
| 风险限制 | 仅关闭活动弹窗并按文档限制榜单；活动计次、发券和抽奖继续正常进行；保留原始订单及中奖事实 |
| 榜单计数 | 仅最终鉴真、鉴假结果计入对应榜；订单提交和结果产生均在活动期内；受限用户按榜单资格处理 |
| 榜单排序与奖励 | 同单数先达到者在前；同人可获两榜奖励。鉴真榜前三每人 200 元及鉴真王者称号；避雷榜前三每人终身免费专鉴及避雷王者称号。获奖资格、实际兑现分开统计 |

普通池 5%、高级池 8% 及风险范围、8 类配置以本轮最新确认优先。Demo 当前普通池 8%、高级池 5% 的配置尚未同步，不作为上线概率核验基准。

## 这次需要回答的业务问题

| 业务问题 | 主要看什么 |
|---|---|
| 新活动带来多少专鉴 | 活动范围内提交人数、订单数；各直接入口贡献；活动参与人均提交单数 |
| 免费赠券能否带来专鉴 | 首赠到账、实际使用、抽后引导曝光、去专鉴点击及关联提交转化 |
| 进度和里程碑是否促成继续鉴定 | 非节点、普通节点、高级节点三组的弹窗触达和再次提交率 |
| 无券用户能否被引导回来 | 无券引导曝光、点击、提交、获券和再次抽奖 |
| 抽奖是否顺畅 | 请求成功率、结果触达率、动画退出及错误原因 |
| 券是否真正被使用 | 按券种、来源、发放批次拆分到账、使用、有效剩余和到期损耗 |
| 未中奖后用户去了哪里 | 安慰互动、稍后离开、再抽、查看奖品、去专鉴及后续订单 |
| 榜单能否带来参与 | 各入口打开榜单、切换榜单、点击去专鉴、关联订单及实际计榜结果 |
| 奖品是否完成交付 | 中奖、权益到账、填写资料、审核、发货/兑现及鉴别券核销 |
| 防刷是否按规则执行 | 正常/预警/受限/解除人数；弹窗抑制、榜单限制与拒发奖品 |

上述转化反映关联链路，不能直接表述为活动产生的净增量。若要判断增量，需要另设可比对照或实验。

## 通用上报规则

### 统计单位

| 单位 | 唯一标识 | 不能混用的情况 |
|---|---|---|
| 用户 | `user_id`，登录前用 `anonymous_id` | 不能用手机号、昵称或设备数代替用户数 |
| 页面访问 | `page_view_id` | 页面重绘、隐藏 iframe 加载不新增访问 |
| 用户操作 | `interaction_id` | 程序触发 click、重复监听不算第二次用户点击 |
| 专鉴流程 | `expert_flow_id` | 同流程重试不新建，用户从新入口明确重新发起才新建 |
| 订单 | `order_id` | 按成功业务订单去重，不能按提交按钮点击计单 |
| AI 结果 | `ai_report_id` | 同一 AI 结果产生多张订单，结果转化只算一次，订单另计 |
| 发券批次 | `ticket_lot_id` | 一个批次可以有多张券，数量取张数，不取列表行数 |
| 券变动 | `ticket_ledger_id` | 一次发放、扣减、过期各自是独立事实，不能相互替代 |
| 抽奖批次 | `draw_request_id` / `draw_batch_id` | 五连是 1 次业务请求、1 个批次 |
| 单次抽取 | `draw_item_id` | 五连有 5 个结果，包含未中奖结果 |
| 奖品权益 | `reward_id` / `voucher_id` | 实物中奖资格到账不等于发货，鉴别券去使用不等于核销 |
| 弹窗 | `popup_instance_id` / `result_view_id` | 动画帧、余额更新和重绘不新增弹窗曝光 |

### 必传公共属性

| 属性 | 含义与填写规则 |
|---|---|
| `event_id` / `event_name` / `event_version` | 单条事件唯一 ID、事件名及字段版本；重发沿用 event_id |
| `occurred_at` / `received_at` | 实际发生时间、采集入库时间分别保留；业务资格按服务端实际时间判断 |
| `user_id` / `anonymous_id` / `session_id` | 稳定用户、匿名访问和会话标识；登录关联后回算 UV，不能将登录前后当两人；会话建议 30 分钟无操作后结束 |
| `activity_id` / `activity_version` | 双11与卡牌独立；聚合奖品页面用 activity_scope=all，具体记录仍带来源活动 |
| `environment` / `is_demo` / `is_test` | 正式、预发、测试及 Demo 区分；模拟用户、模拟时钟和场景重置均不能进入正式看板 |
| `platform` / `app_version` | Web/小程序等渠道和版本，用于定位版本差异 |
| `page_id` / `page_view_id` / `surface` | 当前逻辑页面、本次访问和承载位置；surface 区分页面、半弹层、弹窗 |
| `entry_id` / `source_page` | 当前直接入口和来源页面；没有来源填 direct，不倒推 |
| `source_click_id` / `attribution_id` | source_click_id 取发起流程那次 interaction_id；attribution_id 串起这一条入口链路，后续页面和业务请求继承 |
| `journey_id` / `upstream_entry_click_id` | 保留“播报→专家页→扭蛋→去专鉴”这类上游导航关系；直接 CTA 与导航导流分别统计，不相加当两张订单。新的独立入口建立新 journey；同链路转页不重建 |
| `category_id` / `category_config_version` | 采用产品品类主数据 ID 和生效版本；展示名不是唯一键；未知品类单列，不强行归入其他活动品类 |
| `campaign_eligible` / `exclude_reason` | 是否属于当前活动范围及排除原因；服务端为最终依据，不能从“是否有弹窗”反推 |
| `risk_status` / `policy_version` | 正常、预警、受限、解除等风险状态及规则版本；可对同一指标分层，不静默删除受限样本 |

字段按适用场景必传：订单事件必须有 order_id，抽取事件必须有 draw_item_id；不适用的关联 ID 填空，不用随机构造 ID。属性中的次数、张数为数值；布尔值与字符串不得混用。

`event_id`、各业务 ID 统一用字符串；时间采用带时区的标准时间或统一毫秒时间戳；数量为整数，概率为 0—1 小数，耗时为毫秒。标准原因码由接口返回，未知值填 unknown 并单独统计。禁止上报原始手机号、收货信息、上传图片、自由输入和审核备注；榜单虽展示脱敏手机号，分析仍使用 user_id，不采集手机号。匿名 ID 也需要按内部数据权限管理。

### 曝光和点击

组件曝光建议统一为至少 50% 可见并持续 1 秒，且页面处于前台、未被其他弹窗遮挡。同一次页面访问按组件及素材去重。循环播报复制的 DOM、自动轮播再出现和来回滚动不重复累计。弹窗实际打开、内容可见时记一次，不要求等待动画完成。

若用户在 1 秒内直接点中真实可见组件，该点击本身证明已看到组件：补记同一组件曝光，并标记 `exposure_method=click_confirmed`，避免点击率分子包含未计曝光的用户。时间达到的曝光使用 `exposure_method=visibility_threshold`。

禁用按钮不记录正常点击；用可用状态曝光分析 0 张、1—4 张、5 张及以上券的机会差异。余额不足、活动未开始/结束、正在抽奖应分别记录。

### 业务成功与异常

前端记录看见什么、点了什么、实际进入哪里；订单、累计、发券、扣券、开奖结果、鉴定最终结论、权益核销和榜单结算由服务端业务事实确认。各侧可以共享关联 ID，但不能重复报同名成功事件。

客户端超时只能标记待确认，不能直接判为业务失败。以同一请求 ID 查询后续结果，最终归入成功或明确失败。未结束请求单列，报表展示成熟请求成功率及待确认数量。

重试复用请求 ID；传输重发复用 event_id；业务重复回调按订单、流水、结果 ID 再去重。页面加载历史记录不得补报新发券、新抽奖或新中奖。事件到达可乱序，关联采用业务 ID 和实际时间，不能只靠接收顺序。

同一业务请求只能落在一个最终状态中。暂时失败后补偿成功，应保留状态变化及版本，计算最终成功率时取同一请求的最新有效终态，不把它同时算入成功和失败。用户明确发起新的抽奖才生成新请求 ID，不能沿用上一轮 ID。

关键业务事件全量采集，不能抽样计算发券数、中奖数、库存和榜单。前端失败后的重传保持原 ID；跨 iframe 明确唯一上报方，隐藏页面不曝光。新增字段或枚举要升级事件/配置版本，并在预发确认接收、关联、去重和报表过滤均正确后上线。

| 来源 | 必须保留的细分 |
|---|---|
| 首页中奖播报 | 播报位、素材/实物奖品 ID；只统计曝光点击，不将模拟播报计为真实中奖 |

| 无券引导 | 当时普通/高级余额、距下一券单数、承载页面 |
| 王者榜 | 入口位置、鉴真/避雷、当时本人排名和资格状态 |

同一点击只采用最具体的一种点击事件。AI 卡去专鉴用 `ai_expert_card_click`；活动引导用 `campaign_expert_cta_click`；原专家首页“立即鉴别”用 `campaign_entry_click`。不再叠加通用按钮事件计入业务点击量。

首页播报、去扭蛋和活动选择属于导航入口，其直接目标是页面或弹窗到达。后续专鉴可通过 journey_id 统计该入口的导流贡献，但订单的直接转化来源仍是实际发起专鉴的 CTA。同一订单可以出现在“导航贡献”和“直接来源”两个不同分析视角中，合计订单必须按 order_id 再去重。

## 数据对账

| 对账项 | 必须满足的关系 |
|---|---|
| 提交与累计 | 每张真实订单仅一份提交成功事实；满足活动时间和品类的订单计次一次；风险关闭弹窗不减少累计单数 |
| 里程碑发券 | 累计 N 单应发普通券 floor(N/2)−floor(N/10)，高级券 floor(N/10)；每日券另计；实际到账不足单列补发异常 |
| 券账本 | 发放张数＋经授权净补偿＝成功消耗＋有效剩余＋未用过期；同一张券不能同时属于已用和未用过期 |
| 抽奖批次 | 每个成功批次扣券张数＝count＝单次结果条数；单抽为 1，五连为 5；全部为同一活动和同一券种 |
| 抽奖结果 | 实物结果＋鉴别券结果＋未中奖结果＝全部单次抽取；首赠固定结果仍计入总抽取，但从常规概率样本单列 |
| 奖品权益 | 除未中奖外，每个结果对应应到账权益；到账失败可重试但不得生成第二份权益；实物到账为领奖资格 |
| 双池实物上限 | 每人每个双11活动两池合计最多一个实物中奖结果；同一五连第一颗已中实物，后续颗需记录新资格状态 |
| 库存 | 按 prize_id 对账发放和剩余库存；库存为零不得继续开出；前端不展示份数不影响库存留痕 |
| 榜单 | 原始结果、计分流水、当前资格、排名快照分别保存；鉴真/鉴假各自统计，同一用户可在两榜获奖 |
| 历史数据 | 卡牌与双11按 activity_id 隔离库存、券有效期和中奖限制；历史数据导入不是当日发奖，不触发新中奖事件 |

概率核验同时展示抽取量、实际比例与生效概率。常规样本按奖池、配置版本、实物资格及库存状态分组；混合样本的期望中奖数为逐颗有效概率之和，不能统一乘以 5% 或 8%。少量抽取的比例偏差不直接判为概率配置错误，先核验首赠排除、概率转移、关联完整和重复上报。

## 上线看板

建议默认展示“今日发生量”和“活动累计”，转化率另按首步进入日期查看。统一支持日期、入口、品类、用户新老、券种、券来源、单抽/五连、首次引导/常规、风险状态及客户端版本筛选。

| 看板 | 展示内容 |
|---|---|
| 活动总览 | 活动入口曝光人数、活动访问人数、专鉴提交人数、活动有效订单数、人均单数、抽奖人数和抽取次数 |
| 转化 | 各入口到专鉴、AI 卡到专鉴、首赠到专鉴、每单弹窗再次专鉴、无券到获券再抽、榜单到专鉴 |
| 券资产 | 普通/高级发放、使用、有效余额、过期；每日/里程碑拆分；应发未发、扣券结果不一致 |
| 结果承接 | 按首赠、常规未中奖、鉴别券、实物分别展示结果触达、安慰互动、复抽、去专鉴和奖品查看 |
| 奖品与榜单 | 各 SKU 中奖、资料保存、审核、发货/交付；鉴别券到账/核销；双榜参榜人数、计分、结算 |
| 运行质量 | 提交失败、发券失败、抽奖待确认/失败、结果未展示、重复事件、缺失关联 ID、活动截止边界异常 |

新老用户至少区分“活动前是否提交过专家订单”和“本活动首次/再次参与”，不要只按注册时间推断。无真实历史资料时标记 unknown。

## 上线前需落实的配置

- 防刷的连续计数严格采用“品类＋品牌＋系列”还是后续描述的“相同品牌”；第 7 次警告与第 8 次限制的边界、跨日计数和换品牌重置规则需产品确认后配置。已明确不影响累计、发券和抽奖。
- 榜单解除限制后是否恢复既有成绩、结算时采用哪一版资格，需要明确；原始订单和结果始终保留，不能直接删除。
- 奖品的运营审核是否覆盖全部奖品、审核与收货信息填写的先后、领奖截止和发货时间，按运营最终流程落实。埋点先分别记录各节点事实，不将任一未定顺序强制作为必经漏斗。
- 将 Demo 的奖池概率同步为普通 5% / 75% / 20%、高级 8% / 72% / 20%；美妆无损和各具体小样 SKU 按实际生效配置接入。
- 开发确认已有事件名、用户 ID、订单 ID、AI 结果 ID 的复用关系；数据平台中同一业务成功只保留一个权威来源。本文 24 小时转化窗口与曝光阈值是统计建议，接入前统一采用。
