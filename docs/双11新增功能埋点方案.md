# 双11专鉴活动新增功能埋点方案

本方案用于开发接入、测试验收和活动复盘，覆盖活动入口、专鉴提交、累计发券、每日赠券、扭蛋抽奖、抽后引导、我的抽奖券、我的奖品、王者榜及防刷规则。核心链路是“看到活动 → 提交专鉴 → 获得抽奖券 → 抽奖 → 再次专鉴”，每一步分别记录用户行为和实际业务结果。

本次交付为埋点设计，尚未接入生产 SDK 或数据平台。表内英文事件名是统一命名建议；已有等价事件优先复用并补齐属性，不能再发一套重复事件。

## 最新业务口径

| 项目 | 统计采用的规则 |
|---|---|
| 活动时间 | 暂定北京时间 2026-10-27 00:00:00（含）至 2026-11-11 00:00:00（不含）；以实际上线配置为准 |
| 限免范围 | 全部用户、全部专家鉴定品类免费；免费资格与参与抽奖活动资格分别记录 |

| AI 转专鉴 | 美妆无损不展示 AI 结果后的专鉴卡片；其余按该入口生效配置判断是否应展示 |

## 这次需要回答的业务问题

| 业务问题 | 主要看什么 |
|---|---|
| 新活动带来多少专鉴 | 活动范围内提交人数、订单数；各直接入口贡献；活动参与人均提交单数 |
| 免费赠券能否带来专鉴 | 首赠到账、实际使用、抽后引导曝光、去专鉴点击及关联提交转化 |
| 进度和里程碑是否促成继续鉴定 | 非节点、普通节点、高级节点三组的弹窗触达和再次提交率 |
| 无券用户能否被引导回来 | 无券引导曝光、点击、提交、获券和再次抽奖 |
| 抽奖是否顺畅 | 请求成功率、结果触达率、动画退出及错误原因 |
| 券是否真正被使用 | 按券种、来源、发放批次拆分到账、使用、有效剩余和到期损耗 |
| 未中奖后用户去了哪里 | 安慰互动、稍后离开、再抽、查看奖品、去专鉴及后续订单 |
| 榜单能否带来参与 | 各入口打开榜单、切换榜单、点击去专鉴、关联订单及实际计榜结果 |
| 奖品是否完成交付 | 中奖、权益到账、填写资料、审核、发货/兑现及鉴别券核销 |
| 防刷是否按规则执行 | 正常/预警/受限/解除人数；弹窗抑制、榜单限制与拒发奖品 |

上述转化反映关联链路，不能直接表述为活动产生的净增量。若要判断增量，需要另设可比对照或实验。

## 通用上报规则

### 统计单位

| 单位 | 唯一标识 | 不能混用的情况 |
|---|---|---|
| 用户 | `user_id`，登录前用 `anonymous_id` | 不能用手机号、昵称或设备数代替用户数 |
| 页面访问 | `page_view_id` | 页面重绘、隐藏 iframe 加载不新增访问 |
| 用户操作 | `interaction_id` | 程序触发 click、重复监听不算第二次用户点击 |
| 专鉴流程 | `expert_flow_id` | 同流程重试不新建，用户从新入口明确重新发起才新建 |
| 订单 | `order_id` | 按成功业务订单去重，不能按提交按钮点击计单 |
| AI 结果 | `ai_report_id` | 同一 AI 结果产生多张订单，结果转化只算一次，订单另计 |
| 发券批次 | `ticket_lot_id` | 一个批次可以有多张券，数量取张数，不取列表行数 |
| 券变动 | `ticket_ledger_id` | 一次发放、扣减、过期各自是独立事实，不能相互替代 |
| 抽奖批次 | `draw_request_id` / `draw_batch_id` | 五连是 1 次业务请求、1 个批次 |
| 单次抽取 | `draw_item_id` | 五连有 5 个结果，包含未中奖结果 |
| 奖品权益 | `reward_id` / `voucher_id` | 实物中奖资格到账不等于发货，鉴别券去使用不等于核销 |
| 弹窗 | `popup_instance_id` / `result_view_id` | 动画帧、余额更新和重绘不新增弹窗曝光 |

### 必传公共属性

| 属性 | 含义与填写规则 |
|---|---|
| `event_id` / `event_name` / `event_version` | 单条事件唯一 ID、事件名及字段版本；重发沿用 event_id |
| `occurred_at` / `received_at` | 实际发生时间、采集入库时间分别保留；业务资格按服务端实际时间判断 |
| `user_id` / `anonymous_id` / `session_id` | 稳定用户、匿名访问和会话标识；登录关联后回算 UV，不能将登录前后当两人；会话建议 30 分钟无操作后结束 |
| `activity_id` / `activity_version` | 双11与卡牌独立；聚合奖品页面用 activity_scope=all，具体记录仍带来源活动 |
| `environment` / `is_demo` / `is_test` | 正式、预发、测试及 Demo 区分；模拟用户、模拟时钟和场景重置均不能进入正式看板 |
| `platform` / `app_version` | Web/小程序等渠道和版本，用于定位版本差异 |
| `page_id` / `page_view_id` / `surface` | 当前逻辑页面、本次访问和承载位置；surface 区分页面、半弹层、弹窗 |
| `entry_id` / `source_page` | 当前直接入口和来源页面；没有来源填 direct，不倒推 |
| `source_click_id` / `attribution_id` | source_click_id 取发起流程那次 interaction_id；attribution_id 串起这一条入口链路，后续页面和业务请求继承 |
| `journey_id` / `upstream_entry_click_id` | 保留“播报→专家页→扭蛋→去专鉴”这类上游导航关系；直接 CTA 与导航导流分别统计，不相加当两张订单。新的独立入口建立新 journey；同链路转页不重建 |
| `category_id` / `category_config_version` | 采用产品品类主数据 ID 和生效版本；展示名不是唯一键；未知品类单列，不强行归入其他活动品类 |
| `campaign_eligible` / `exclude_reason` | 是否属于当前活动范围及排除原因；服务端为最终依据，不能从“是否有弹窗”反推 |
| `risk_status` / `policy_version` | 正常、预警、受限、解除等风险状态及规则版本；可对同一指标分层，不静默删除受限样本 |

字段按适用场景必传：订单事件必须有 order_id，抽取事件必须有 draw_item_id；不适用的关联 ID 填空，不用随机构造 ID。属性中的次数、张数为数值；布尔值与字符串不得混用。

`event_id`、各业务 ID 统一用字符串；时间采用带时区的标准时间或统一毫秒时间戳；数量为整数，概率为 0—1 小数，耗时为毫秒。标准原因码由接口返回，未知值填 unknown 并单独统计。禁止上报原始手机号、收货信息、上传图片、自由输入和审核备注；榜单虽展示脱敏手机号，分析仍使用 user_id，不采集手机号。匿名 ID 也需要按内部数据权限管理。

### 曝光和点击

组件曝光建议统一为至少 50% 可见并持续 1 秒，且页面处于前台、未被其他弹窗遮挡。同一次页面访问按组件及素材去重。循环播报复制的 DOM、自动轮播再出现和来回滚动不重复累计。弹窗实际打开、内容可见时记一次，不要求等待动画完成。

若用户在 1 秒内直接点中真实可见组件，该点击本身证明已看到组件：补记同一组件曝光，并标记 `exposure_method=click_confirmed`，避免点击率分子包含未计曝光的用户。时间达到的曝光使用 `exposure_method=visibility_threshold`。

禁用按钮不记录正常点击；用可用状态曝光分析 0 张、1—4 张、5 张及以上券的机会差异。余额不足、活动未开始/结束、正在抽奖应分别记录。

### 业务成功与异常

前端记录看见什么、点了什么、实际进入哪里；订单、累计、发券、扣券、开奖结果、鉴定最终结论、权益核销和榜单结算由服务端业务事实确认。各侧可以共享关联 ID，但不能重复报同名成功事件。

客户端超时只能标记待确认，不能直接判为业务失败。以同一请求 ID 查询后续结果，最终归入成功或明确失败。未结束请求单列，报表展示成熟请求成功率及待确认数量。

重试复用请求 ID；传输重发复用 event_id；业务重复回调按订单、流水、结果 ID 再去重。页面加载历史记录不得补报新发券、新抽奖或新中奖。事件到达可乱序，关联采用业务 ID 和实际时间，不能只靠接收顺序。

同一业务请求只能落在一个最终状态中。暂时失败后补偿成功，应保留状态变化及版本，计算最终成功率时取同一请求的最新有效终态，不把它同时算入成功和失败。用户明确发起新的抽奖才生成新请求 ID，不能沿用上一轮 ID。

关键业务事件全量采集，不能抽样计算发券数、中奖数、库存和榜单。前端失败后的重传保持原 ID；跨 iframe 明确唯一上报方，隐藏页面不曝光。新增字段或枚举要升级事件/配置版本，并在预发确认接收、关联、去重和报表过滤均正确后上线。

## 分板块埋点表

P0 为上线前需闭环的业务和转化事件；P1 为体验优化及细分诊断。以下均为建议接入的事件，不表示 Demo 已上报。属性列在公共属性基础上补充；服务端事件需与真实业务接口接入。

共 65 个事件：P0 46 个、P1 19 个。按功能板块查阅；前端负责行为，服务端负责业务事实。

### 入口

#### 活动相关页面访问 · P0 · 前端

事件名：`campaign_page_view`

- **触发：** 首页、专家页、双11抽奖页或我的奖品页完成激活，处于前台且主体实际可见时上报。iframe ready、activate、visibility 合并识别为一次逻辑到达。
- **去重：** 同一 page_view_id + page_id 一次；刷新或离开后重新进入产生新的 page_view_id。
- **记录字段：** 公共字段；page_id 页面标识；source_page 上一逻辑页面；entry_id 入口；attribution_id 本次来源链路；activity_status 未开始/进行中/已结束；is_demo 演示标识。页面访问不代表活动参与。
- **用于分析：** 衡量真实页面到达量并承接入口转化。

#### 活动入口曝光 · P0 · 前端

事件名：`campaign_entry_view`

- **触发：** 首页中奖播报、专家Tab限免角标、专家页立即鉴别CTA、专家机台、去扭蛋、王者榜、抽奖中心导航及活动选择卡实际进入可视区域并满足统一曝光阈值后上报。
- **去重：** page_view_id + entry_id + creative_id 一次；循环播报的复制 DOM、来回滚动与重绘不重复。
- **记录字段：** 公共字段；entry_id 区分 winner_ticker/expert_tab_free_badge/expert_identify_cta/expert_machine/expert_draw_button/expert_rank/drawer_lottery/activity_card 等；creative_id 内容标识；prize_id 播报奖品；render_variant 展示版本；activity_status。expert_tab_free_badge表示专家Tab限免角标，expert_identify_cta表示立即鉴别CTA；播报不上传昵称、手机号或整段用户文案。
- **用于分析：** 统计活动入口覆盖及各入口点击率。

#### 活动入口点击 · P0 · 前端

事件名：`campaign_entry_click`

- **触发：** 用户真实点击已展示入口且触发入口处理时上报；程序 .click()、拖动后被拦截的点击及禁用控件不计。
- **去重：** 每次真实交互生成 interaction_id；同一 interaction_id 一次。
- **记录字段：** 公共字段；entry_id 复用曝光枚举，含expert_tab_free_badge（专家Tab限免角标）及expert_identify_cta（立即鉴别CTA）；creative_id；source_page；target_page；target_surface 页面/弹窗；interaction_id；attribution_id。角标由所属Tab统一承接时只记一次入口点击，不重复记录父子节点；同一入口事件只由实际交互所在前端上报。
- **用于分析：** 比较入口吸引力并关联到达、抽奖与专鉴。

#### 活动规则查看 · P1 · 前端

事件名：`campaign_rule_view`

- **触发：** 活动规则或奖池规则内容实际打开并可见时上报，包含榜单规则入口。
- **去重：** rule_view_id 一次；内容重绘不新增；关闭后再次打开可新增。
- **记录字段：** 公共字段；rule_view_id；rule_type activity/pool/leaderboard；entry_id；source_popup_id；rule_version；selected_pool；ranking_kind。
- **用于分析：** 识别规则查看需求及对后续参与的影响。

### AI转专鉴

## 漏斗指标与验收

本文为埋点设计及验收口径，尚未接入生产 SDK 或数据平台；与主方案、事件字典共同使用。

### 统计基础

统计日期、每日赠券刷新及活动起止均使用北京时间。活动时间暂定为 2026-10-27 00:00:00（含）至 2026-11-11 00:00:00（不含），以上线配置及服务端时间判断业务资格。

活动品类按 8 类预留：美妆、美妆无损、包袋、鞋靴、服饰、手表、3C数码、3C无损。实际参与范围取该订单提交时生效的上线配置，保存配置版本和标准品类 ID；Demo 旧名称到标准品类的映射由主数据配置确认，不按文案猜测。

| 统计单位 | 去重依据 | 使用范围 |
|---|---|---|
| 人 | 稳定 `user_id`，登录前 `anonymous_id` | 登录关联后合并为同一人，不把登录前后重复计数 |
| 曝光会话 | 用户 ID＋会话 ID＋入口 | 入口漏斗；会话建议连续 30 分钟无操作结束 |
| 鉴定流程 | `expert_flow_id` | 一次发起、选品、传图、提交过程 |
| 专鉴订单 | 订单 ID | 提交单数、活动累计单数、最终鉴定结果 |
| AI 结果 | `ai_report_id` | AI 卡片到专鉴转化 |
| 抽奖券 | 券 ID 或发券批次内数量流水 | 发放、消耗、过期张数 |
| 抽奖批次 | 抽奖请求 ID | 单抽/五连各为一个批次 |
| 单次开奖结果 | 结果 ID | 五连产生五个结果，计算中奖率 |

正式统计排除 Demo、测试账号、模拟时钟、预置榜单、指定中奖场景等数据。订单、发券、扣券、开奖、最终结果、领奖采用业务成功事实；点击或动画完成不能替代成功。

### 曝光、链路与观察窗口

- 组件至少 50% 可见并持续 1 秒、页面前台且未被遮挡才计曝光；原始事件按 `page_view_id`＋组件/素材 ID 去重。1 秒前真实点击可见组件，补记曝光并标记 `exposure_method=click_confirmed`，同键不再重复；正常计时曝光标记 `visibility_threshold`。弹窗按实际打开且内容可见的实例计一次。
- 原始曝光按页面访问采集，报表再聚合：入口按用户＋会话＋入口、AI 卡按 `ai_report_id`、进度弹窗按原订单 ID。刷新产生新页面曝光，不代表这些漏斗新增一名用户、一份报告或一张订单。跨日按对象首次进入该漏斗的日期归 cohort。
- 真实点击生成 `interaction_id`；发起流程时将其作为 `source_click_id`，创建 `expert_flow_id`，订单继承。选品、传图、查看规则不改来源；从新入口明确重新发起才建新流程。一张订单只归因一个直接入口。
- 首页播报、去扭蛋、活动选择等导航链用 `journey_id`、`upstream_entry_click_id` 保留上游来源；进入活动后点击去专鉴，直接来源仍是该 CTA 的 `source_click_id`。导航贡献与直接归因属于同一订单的不同分析层，不可相加成新增订单。
- AI 链路携带 `ai_report_id`；进度弹窗携带原订单 ID；抽后引导携带批次和首次券 ID。浏览但没有对应点击不能算直接转化。
- 漏斗按进入首步的日期形成 cohort，后续步骤只统计这批对象，且按时间顺序发生。日报分别展示“当日发生量”和“进入 cohort 的后续转化”，不拿当天曝光人数除以当天所有提交人数。
- 转专鉴漏斗建议从该链首步起观察 24 小时，截止为“首步时间＋24 小时”和“活动结束时间”的较早者；首次赠券的抽后转专鉴链从结果引导曝光起算。窗口未结束标“观察中”，结束后标“成熟”；活动结束后提交另算普通业务，不算本活动转化。此为统计建议，接入前统一配置。
- 每日券追踪至当日到期，里程碑券追踪至活动结束。领奖截止尚未确定，先按开奖 cohort 展示截至观察日的兑现状态与耗时，不把未完成者直接判为流失。

### 活动入口到专鉴提交

导航入口与直接去专鉴 CTA 分开统计，单位均为“入口曝光会话”。点击须属于原曝光会话；后续关联流程可跨会话在上述窗口内完成，仍归原曝光会话。

导航漏斗：**首页中奖播报／去扭蛋／活动选择曝光→点击该入口→目标页面或弹窗实际到达**。点击率＝点击会话数÷曝光会话数；到达率＝成功到达会话数÷点击会话数。导航点击不能记成点击去专鉴，程序切换路由也不能代替实际到达。

导航后续可统计“经去专鉴 CTA 产生成功订单的导流会话数÷导航曝光会话数”，名称为导航导流转化率，须由 `journey_id`、`upstream_entry_click_id` 和实际 CTA 串联。导航带来的订单数仅作导流贡献，不能与直接 CTA 订单贡献相加。

直接 CTA 漏斗适用于专家首页“立即鉴别”、无券“去专鉴”、进度“去专鉴”等真实发起鉴定的操作：

| 步骤 | 统计什么、如何去重 |
|---|---|
| 入口曝光 | 有效看到该入口的曝光会话数 |
| 点击去专鉴 | 上一步会话内发生对应点击的会话数 |
| 品类选择完成 | 通过该点击进入流程且确认品类的会话数 |
| 到达传图页 | 对应流程成功进入传图页的会话数 |
| 点击提交 | 对应流程点击提交的会话数 |
| 提交成功 | 对应流程至少产生一张成功订单的会话数 |

逐步转化率＝下一步会话数÷上一步会话数；整体转化率＝提交成功会话数÷入口曝光会话数。入口点击率＝点击会话数÷曝光会话数。

同时单列成功提交人数、成功订单数、活动范围内订单数，分别按用户 ID、订单 ID 去重。非活动品类成功提交仍是专鉴业务成功，但不算活动有效订单。带入商品、无需选品的入口单独拆分路径，不把“跳过选品”当作流失。

### AI 结果卡片到专鉴提交

单位统一为 `ai_report_id`。分母只纳入**用户实际进入前台、报告数据就绪且按该入口配置应展示卡片**的报告；取 `ai_report_ready` 的 `card_should_show=true`，美妆无损排除。后台已生成但用户未访问的报告不进分母。

| 步骤 | 统计什么、如何去重 |
|---|---|
| 前台就绪且应展示卡片的报告 | 实际进入报告页、就绪且 `card_should_show=true` 的 `ai_report_id` 数 |
| 专家卡片曝光 | 其中实际看到专家卡片的结果数 |
| 点击去专鉴 | 其中发生卡片去专鉴点击的结果数 |
| 带入商品到传图页 | 对应点击成功进入传图流程的结果数 |
| 专鉴提交成功 | 关联至少一张成功专鉴订单的 AI 结果数 |

卡片触达率＝上述前台报告中实际曝光卡片的报告数÷前台就绪且应展示卡片的报告数；点击率＝点击报告数÷曝光报告数；提交转化率＝关联成功订单的报告数÷卡片曝光报告数。先按页面访问取最新有效展示决策、关联该次卡片曝光，再按 `ai_report_id` 合并；同报告多次符合条件的访问只计 1，cohort 取首次符合条件访问日期。不应展示却曝光单列为配置异常，不混入分子。

同一 AI 结果多次点击、产生多张订单，转化的结果数最多计 1，订单贡献另按订单 ID 累计。AI 路径不要求经过品类弹层。“查看详情”仅统计点击，未建设的详情页不统计虚构曝光。

### 首次赠券引导到专鉴

以首次引导券为线索，人数按活动内合并后的用户身份去重，关联具体券及消耗记录。**主链为“首次赠券到账→使用原券”**，不要求先看到介绍弹窗。

| 步骤 | 统计什么、如何去重 |
|---|---|
| 首次赠券到账 | 实际获得首次引导券的人数 |
| 使用首次赠券 | 到账 cohort 中实际消耗原券并开奖成功的人数，不以介绍曝光为前提 |
| 抽后引导曝光 | 其中看到对应抽后领券引导的人数 |
| 点击去专鉴 | 其中点击该引导的人数 |
| 专鉴提交成功 | 其中经该点击发起流程并提交成功的人数 |

赠券使用率＝消耗首次券人数÷首次券到账人数。介绍弹窗为独立诊断分支：介绍触达率＝介绍曝光人数÷应展示介绍人数，受风险策略关闭者单列。抽后引导转化率＝关联提交成功人数÷抽后引导曝光人数；其窗口从该引导曝光起算，不能把未看介绍但从中心使用券的人判为流失。

选择“稍后再用”后从中心使用原券仍关联本链路。首次券过期后，不把次日赠券接到该链路。首次强制未中奖只属于指定赠券，不等于每个用户的第一次抽奖；五连中含该券时，只将对应那一个结果标记为引导结果。

### 订单进度弹窗到再次专鉴

单位统一为“触发进度的原订单 ID”，从每张成功的活动订单建立 cohort。

| 步骤 | 统计什么、如何去重 |
|---|---|
| 应展示进度 | 提交成功、符合活动条件且有效弹窗决策 `should_show=true` 的原订单数；同意图决策修订取最新有效版本 |
| 进度弹窗曝光 | 上述订单中实际展示进度弹窗的订单数 |
| 点击去专鉴 | 上述订单中发生弹窗去专鉴点击的订单数 |
| 再次到达传图页 | 上述点击产生的新流程进入传图页的原订单数 |
| 新订单提交成功 | 新流程成功提交另一张订单的原订单数 |

触达率＝实际曝光原订单数÷应展示原订单数；再专鉴转化率＝带来新成功订单的原订单数÷进度弹窗曝光原订单数。新订单不能与原订单相同。同一弹窗带来多张订单，原订单转化最多计 1，新订单贡献另计。

按“未到获券节点／普通券节点／高级券节点”拆分。每个活动订单均应触发进度，不能只测获券订单。风险策略关闭的订单单列，排除在应弹分母外；不得把策略抑制计为弹窗故障。

### 抽奖与领奖

抽奖漏斗按请求统计：正式发起→扣券及结果生成成功→结果弹窗曝光，以请求 ID 关联批次。成熟请求成功率＝成功请求数÷已有成功/明确失败终态的请求数；待确认请求单列，客户端超时不直接记业务失败。截至当前成功覆盖率可另算“成功请求数÷全部发起请求数”，不得混称最终成功率。结果触达率＝实际展示结果批次数÷成功批次数；被策略关闭的结果弹窗需单列，在技术触达率中只用应展示批次为分母。重复请求重试按同一请求 ID 去重。

单抽是 1 个批次、1 张券、1 个结果；五连是 1 个批次、5 张券、5 个结果。普通池与高级池分别统计。

- 实物/鉴别券中奖率＝该类结果数÷可比较的单次结果总数。
- 常规概率核验排除首次引导券对应结果；五连其余四个结果仍纳入。
- 最新标准：普通池实物 5%、鉴别券 75%、未中奖 20%；高级池实物 8%、鉴别券 72%、未中奖 20%。按实际规则版本核验，不能以 Demo 旧概率为准。
- 按个人实物资格、库存状态及转移原因拆分。实物不可中时转给鉴别券，目标为鉴别券 80%、未中奖 20%；该样本不可与未转移的普通 75%/高级 72% 直接比较。
- 结果动画关闭、刷新或未看完，不改变成功扣券、开奖事实。

实物领奖按单个中奖结果关联 `reward_id`，分别记录中奖、资格到账、资料保存、审核结论、发货和交付事实。**资料与审核不设固定先后顺序**，待运营确认后再配置必经路径。资料完成率＝需资料且保存成功的奖品数÷需资料的实物奖品数；审核通过率＝审核通过奖品数÷已完成审核奖品数，仅纳入实际需审核者；兑现率＝已交付实物奖品数÷实物中奖奖品数。发货、送达、待审、拒发分别展示，发货不等于已交付。

专家线上鉴别券到账率＝到账成功的中奖结果数÷鉴别券中奖结果数；后续使用按 `voucher_id` 统计，与抽奖券消耗分开。是否全部鉴别券均需前置审核尚未明确，不将审核自行设为必经条件。资格入账、最终到账若涉及两个事件，按同一权益 ID 去重，不能加成两份奖品。审核拒发保留中奖事实，不回写为未中奖。

### 榜单引流及抽奖券指标

榜单引流按用户＋会话＋入口去重：入口曝光→点击→榜单曝光→去专鉴点击→关联提交成功。入口点击率＝点击会话数÷入口曝光会话数；榜单转化率＝关联成功会话数÷榜单曝光会话数。默认榜单和切换后实际展示的榜单分别归属对应 Tab；跨 Tab 汇总人数再次去重。一张订单只有一个直接来源，不因此前看过榜单重复归因。

榜单成绩按最终鉴真/鉴假订单数累计，要求提交和最终结果均落在活动期间；无法判断不入榜。活动结束后才出结果，提交事实保留，榜单不加分。

抽奖券按发放 cohort、券种和来源统计：累计发放张数、成功消耗张数、剩余有效张数、未用过期张数。使用率＝该批次成功消耗张数÷该批次发放张数；最终过期率＝到期未用张数÷发放张数。未到期批次标注“截至当前”，成熟批次单独比较。一批券可部分已用、部分过期，不能按列表条数或整批状态统计。

累计 N 单活动有效订单，应发普通券 `floor(N/2)-floor(N/10)` 张、高级券 `floor(N/10)` 张；每日赠券另计。该公式用于核对业务流水，实际获券指标仍取真实到账。跨天不清零，第 10/20…单不重复发普通券。

### 防刷与风险决策

已确认：风险策略仅关闭活动弹窗并按规则限制榜单，不影响活动累计、发券和抽奖。因此风险用户的真实成功订单、发券及抽奖均保留在对应业务指标中；“正常用户”分层可另算，但不能悄悄删除风险样本。

每笔风险判断保留关联订单、决策 ID、规则版本、连续计数、匹配品类/品牌/系列、当前限制和解除原因。警告曝光、弹窗实际被抑制、榜单限制执行、换品牌解除分别记录。连续计数粒度、7/8 单边界及恢复榜单的历史成绩处理仍以上线确认配置为准，不自定规则。

原始提交事实与榜单资格独立：保留原始鉴真/鉴假结果及当时资格变化，另外计算当前有效榜单成绩。警告触达率只用应警告者为分母；弹窗触达率只用应弹者为分母。运营审核因刷单拒发奖品，新增审核拒发事实，不删除中奖记录，不反向改变抽奖成功率。

### 指标与事件字典映射

以下名称对应 `event-catalog.json`，只表示接入方案。每一行仍按上文指定单位聚合，不以事件条数直接当作转化人数。

| 指标节点 | 对应事件或事实 |
|---|---|
| 导航曝光、点击、实际到达 | `campaign_entry_view`、`campaign_entry_click`→目标 `campaign_page_view` 或 `campaign_popup_view`；保留 journey_id、upstream_entry_click_id，导航点击不等于去专鉴 |
| 直接去专鉴点击 | 原“立即鉴别”用 `campaign_entry_click` 对应 entry_id；活动专用 CTA 用 `campaign_expert_cta_click`，同一点击不重复报通用事件 |
| 选品、传图、提交 | `expert_category_select`、`expert_selection_confirm`、`expert_upload_page_view`、`expert_submit_click`、`expert_order_submit_success`；活动计次取 `campaign_order_counted` 的 counted |
| AI 卡漏斗 | 分母取 `ai_report_ready` 的 card_should_show=true；`ai_expert_card_view`、`ai_expert_card_click` 的 expert、`ai_expert_handoff_result` 的 success，再关联提交成功 |
| 首次券到账、实际使用 | `campaign_ticket_grant_success` 的首赠标记；`campaign_ticket_state_changed` 的 consume 联合 `draw_batch_success`、`draw_item_result`，按原券关联 |
| 首赠介绍、抽后引导 | `campaign_popup_decision` 的首赠 should_show=true 给出应弹分母；`campaign_popup_view` 的 first_gift 为独立诊断；`draw_result_view` 的首次引导标记→`campaign_expert_cta_click`→关联提交成功 |
| 每单进度、再次专鉴 | 应弹取 `campaign_popup_decision` 的 should_show=true；`campaign_popup_view` 的 order_progress/ticket_arrival→`campaign_expert_cta_click`→关联新订单成功；同原订单合并去重 |
| 各位置进度条真实可见 | `campaign_progress_view` 按 progress_surface 拆分；不把弹窗整体曝光代替进度条实际曝光，不逐里程碑重复计数 |

### 上线验收

| 场景 | 必须核对 |
|---|---|
| 刷新、重复点击、网络重传 | 用户/订单/发券/扣券/结果各按本单位去重，成功事实不重复 |
| 首次稍后用、当天过期、次日赠券 | 精确关联首次那张券；不得把次日正常券记为首次强制结果 |
| 五连包含首次券 | 1 批次、5 张券、5 结果；仅 1 结果排除常规概率核验 |
| 第 1/2/9/10/20 单、跨日累计 | 节点正确，普通与高级不重发；非节点仍有应弹记录 |
| 8 类配置及非活动品类 | 以生效版本判定；其他品类免费提交不混入活动累计 |
| AI 同结果产生多张专鉴单 | AI 结果转化计 1，真实订单分别计数；不强制经历选品 |
| 早于 1 秒点击、反复刷新 | 补记 click_confirmed；同页面同组件只曝光一次，AI/订单漏斗再按自身单位合并 |
| 美妆无损 AI 报告 | 不入应展示卡片分母；异常出现卡片单列，不误算正常触达 |
| 进度弹窗再次提交 | 原订单、新流程、新订单链路完整，分母为原订单 |
| 风险关闭弹窗但继续提交/抽奖 | 累计、发券、抽奖正常计数；受抑制订单不算触达失败 |
| 风险限制、换品牌解除、审核拒发 | 状态可追溯；不删除原始订单、最终结果及中奖事实 |
| 个人实物上限、库存耗尽 | 概率转移原因可区分，常规概率对比样本正确 |
| 最新奖池与履约节点 | 普通 5%/75%/20%、高级 8%/72%/20%；不强制资料与审核顺序，不默认所有鉴别券前置审核 |
| 临界时间及跨日窗口 | 北京时间准确，截止后结果不入榜；观察中与成熟 cohort 分开 |
| Demo/预置数据/模拟场景 | 可做验收，正式看板全部排除；不采集真实手机号或收货内容 |

## 数据对账

| 对账项 | 必须满足的关系 |
|---|---|
| 提交与累计 | 每张真实订单仅一份提交成功事实；满足活动时间和品类的订单计次一次；风险关闭弹窗不减少累计单数 |
| 里程碑发券 | 累计 N 单应发普通券 floor(N/2)−floor(N/10)，高级券 floor(N/10)；每日券另计；实际到账不足单列补发异常 |
| 券账本 | 发放张数＋经授权净补偿＝成功消耗＋有效剩余＋未用过期；同一张券不能同时属于已用和未用过期 |
| 抽奖批次 | 每个成功批次扣券张数＝count＝单次结果条数；单抽为 1，五连为 5；全部为同一活动和同一券种 |
| 抽奖结果 | 实物结果＋鉴别券结果＋未中奖结果＝全部单次抽取；首赠固定结果仍计入总抽取，但从常规概率样本单列 |
| 奖品权益 | 除未中奖外，每个结果对应应到账权益；到账失败可重试但不得生成第二份权益；实物到账为领奖资格 |
| 双池实物上限 | 每人每个双11活动两池合计最多一个实物中奖结果；同一五连第一颗已中实物，后续颗需记录新资格状态 |
| 库存 | 按 prize_id 对账发放和剩余库存；库存为零不得继续开出；前端不展示份数不影响库存留痕 |
| 榜单 | 原始结果、计分流水、当前资格、排名快照分别保存；鉴真/鉴假各自统计，同一用户可在两榜获奖 |
| 历史数据 | 卡牌与双11按 activity_id 隔离库存、券有效期和中奖限制；历史数据导入不是当日发奖，不触发新中奖事件 |

概率核验同时展示抽取量、实际比例与生效概率。常规样本按奖池、配置版本、实物资格及库存状态分组；混合样本的期望中奖数为逐颗有效概率之和，不能统一乘以 5% 或 8%。少量抽取的比例偏差不直接判为概率配置错误，先核验首赠排除、概率转移、关联完整和重复上报。

## 上线看板

建议默认展示“今日发生量”和“活动累计”，转化率另按首步进入日期查看。统一支持日期、入口、品类、用户新老、券种、券来源、单抽/五连、首次引导/常规、风险状态及客户端版本筛选。

| 看板 | 展示内容 |
|---|---|
| 活动总览 | 活动入口曝光人数、活动访问人数、专鉴提交人数、活动有效订单数、人均单数、抽奖人数和抽取次数 |
| 转化 | 各入口到专鉴、AI 卡到专鉴、首赠到专鉴、每单弹窗再次专鉴、无券到获券再抽、榜单到专鉴 |
| 券资产 | 普通/高级发放、使用、有效余额、过期；每日/里程碑拆分；应发未发、扣券结果不一致 |
| 结果承接 | 按首赠、常规未中奖、鉴别券、实物分别展示结果触达、安慰互动、复抽、去专鉴和奖品查看 |
| 奖品与榜单 | 各 SKU 中奖、资料保存、审核、发货/交付；鉴别券到账/核销；双榜参榜人数、计分、结算 |
| 运行质量 | 提交失败、发券失败、抽奖待确认/失败、结果未展示、重复事件、缺失关联 ID、活动截止边界异常 |

新老用户至少区分“活动前是否提交过专家订单”和“本活动首次/再次参与”，不要只按注册时间推断。无真实历史资料时标记 unknown。

## 上线前需落实的配置

- 防刷的连续计数严格采用“品类＋品牌＋系列”还是后续描述的“相同品牌”；第 7 次警告与第 8 次限制的边界、跨日计数和换品牌重置规则需产品确认后配置。已明确不影响累计、发券和抽奖。
- 榜单解除限制后是否恢复既有成绩、结算时采用哪一版资格，需要明确；原始订单和结果始终保留，不能直接删除。
- 奖品的运营审核是否覆盖全部奖品、审核与收货信息填写的先后、领奖截止和发货时间，按运营最终流程落实。埋点先分别记录各节点事实，不将任一未定顺序强制作为必经漏斗。
- 将 Demo 的奖池概率同步为普通 5% / 75% / 20%、高级 8% / 72% / 20%；美妆无损和各具体小样 SKU 按实际生效配置接入。
- 开发确认已有事件名、用户 ID、订单 ID、AI 结果 ID 的复用关系；数据平台中同一业务成功只保留一个权威来源。本文 24 小时转化窗口与曝光阈值是统计建议，接入前统一采用。
